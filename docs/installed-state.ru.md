# Установка и проверка 4 октября 2026

После перезапуска Zed проверены реально работающие процессы на обеих платформах. Windows запустил `.codex/context-accounting-fix/0.159.2-reasoning-0ae0125731/bin/codex.exe`, Ubuntu — соответствующий `bin/codex`. Контрольные суммы совпали с установочными манифестами:

В обеих ОС установлена версия `0.159.2-reasoning-0ae0125731`. Основа — upstream Codex 0.159.2, коммит `ff6aec96948b70d94983af2641a6b67c94faeff5`; SHA-256 патча — `0ae0125731fc0059b31043127067db1fe9d7eafaceebdb523b334a8cde779022`.

Обычный агент Zed `agent_servers.codex-acp` сохраняет `type: registry`. Его `env.NODE_OPTIONS` загружает переносимый `preload.cjs` из домашней папки соответствующей ОС и выбирает установленный исправленный файл. В панели моделей отдельный агент не требуется. Текущий выбор при проверке — GPT-6.1 Sol, xhigh; исправление учёта определяется режимом API модели и не привязано к одному имени модели.

В обоих `~/.codex/config.toml` сохранены настройки:

```toml
model_context_window = 922000
model_auto_compact_token_limit = 922000
model_auto_compact_token_limit_scope = "body_after_prefix"
model_post_turn_compact_threshold_percent = 0
```

`model_catalog_json` указывает на абсолютный путь `~/.codex/codex-1m/catalog.json` своей ОС. Каталог создан `scripts/create-catalog.py` и отличается от списка моделей сервера двумя полями у семи моделей GPT-6 и GPT-5.6: `max_context_window` равен 922 000 вместо 872 000, `effective_context_window_percent` — 97 вместо 95. Compact запускается при 894 340 токенах, запас до предела входа — 27 660. Долю 97% выбрал владелец установки вместо серверных 95% ради большего окна. Каталог и установленная папка `~/.codex/context-accounting-fix` необходимы для работы; это не временные файлы сборки. Прежние конфигурации и каталоги сохранены рядом с новыми с окончанием `.bak-2026-10-04-window-1050000`.

922 000 — максимум входа по документации OpenAI для этих моделей: окно 1 050 000 включает ещё 128 000 токенов ответа. До вечера 4 октября в обеих ОС стояли окно 1 050 000, порог 1 050 000 и каталог с долей 100%. В рабочем чате Ubuntu запрос на 922 856 входных токенов прошёл, а следующий, оценённый клиентом в 925 227, сервер отклонил в 19:05:42 UTC с `context_length_exceeded`. Клиент в этот момент видел предел 1 050 000 и compact не запускал.

Причина раннего compact: при серверном учёте 737 658 токенов клиент повторно добавлял 313 149 токенов старых зашифрованных рассуждений и 946 локальных токенов, получая 1 051 753. Патч сохраняет правильный контракт учёта для предыдущего ответа и устанавливает его для модели фактического запроса. Подробнее — README и исходный патч.

При сборке Windows из Ubuntu SQL-миграции должны иметь CRLF: все 73 контрольные суммы SQLx в существующих Windows-базах соответствовали именно CRLF. Новая сборка с CRLF успешно открыла рабочий профиль. Базы данных и история чатов для этого не изменялись.

Проверки: 7 интеграционных тестов учёта контекста, 5 тестов `codex-chatgpt`, форматирование, release-сборки обеих платформ и `initialize`/`session/new` через штатный ACP на существующих профилях. Проверка ACP не отправляла запросов к модели. Полный набор тестов upstream не выполнялся. В рабочем чате Ubuntu после установки контекст дошёл до 922 856 входных токенов без преждевременного compact, то есть повторный учёт рассуждений устранён. Срабатывание compact на новом пороге 894 340 в рабочем чате ещё не наблюдалось. После смены настроек 4 октября `codex debug models` и `scripts/probe.cjs` пройдены в обеих ОС: исправленный файл загружает каталог с 922 000 и 97%, `initialize` и `session/new` через штатный ACP успешны, запросов к модели не было.

5 октября патч проверен на исходниках Codex 0.160.0 (коммит `a956835d020762cb2b570053af06f643a11c0ecc`): накладывается без изменений, 7 интеграционных проверок и 5 тестов `codex-chatgpt` проходят, а без двух правок исходников четыре новых случая падают с лишним запросом compact. Исполняемые файлы из 0.160.0 не собирались и не устанавливались.

Для повторной установки используйте скрипты и инструкции README. После обновления файлов уже подключённый агент переключается через меню панели чата `⋯ → Reload Agent`, когда текущая работа закончена. Установка не зависит от временных каталогов исходников и сборки.
