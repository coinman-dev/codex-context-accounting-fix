# Установка и проверка 4 октября 2026

После перезапуска Zed проверены реально работающие процессы на обеих платформах. Windows запустил `.codex/context-accounting-fix/0.159.2-reasoning-0ae0125731/bin/codex.exe`, Ubuntu — соответствующий `bin/codex`. Контрольные суммы совпали с установочными манифестами:

| Платформа | SHA-256 основного файла |
| --- | --- |
| Windows | `35fd7ede96b944ceeba670c82ccd590982fa390251b55d7b25cc92d79f551a82` |
| Ubuntu | `dd32d57a00f18bbae5a2c41201078630a3403e1562d8e90ad4ebd90d6d89b3d9` |

В обеих ОС установлена версия `0.159.2-reasoning-0ae0125731`. Основа — upstream Codex 0.159.2, коммит `ff6aec96948b70d94983af2641a6b67c94faeff5`; SHA-256 патча — `0ae0125731fc0059b31043127067db1fe9d7eafaceebdb523b334a8cde779022`.

Обычный агент Zed `agent_servers.codex-acp` сохраняет `type: registry`. Его `env.NODE_OPTIONS` загружает переносимый `preload.cjs` из домашней папки соответствующей ОС и выбирает установленный исправленный файл. В панели моделей отдельный агент не требуется. Текущий выбор при проверке — GPT-6.1 Sol, xhigh; исправление учёта определяется режимом API модели и не привязано к одному имени модели.

В обоих `~/.codex/config.toml` сохранены настройки:

```toml
model_context_window = 1050000
model_auto_compact_token_limit = 1050000
model_auto_compact_token_limit_scope = "body_after_prefix"
model_post_turn_compact_threshold_percent = 0
```

`model_catalog_json` указывает на абсолютный путь `~/.codex/codex-1m/catalog.json` своей ОС. Каталог и установленная папка `~/.codex/context-accounting-fix` необходимы для работы; это не временные файлы сборки. Каталог не увеличивает серверный предел модели.

Причина раннего compact: при серверном учёте 737 658 токенов клиент повторно добавлял 313 149 токенов старых зашифрованных рассуждений и 946 локальных токенов, получая 1 051 753. Патч сохраняет правильный контракт учёта для предыдущего ответа и устанавливает его для модели фактического запроса. Подробнее — README и исходный патч.

При сборке Windows из Ubuntu SQL-миграции должны иметь CRLF: все 73 контрольные суммы SQLx в существующих Windows-базах соответствовали именно CRLF. Новая сборка с CRLF успешно открыла рабочий профиль. Базы данных и история чатов для этого не изменялись.

Проверки: 7 интеграционных тестов учёта контекста, 5 тестов `codex-chatgpt`, форматирование, release-сборки обеих платформ и `initialize`/`session/new` через штатный ACP на существующих профилях. Проверка ACP не отправляла запросов к модели. Полный набор тестов upstream и реальный запрос на 1,05 млн токенов не выполнялись; фактическая точка compact в длинном рабочем чате ещё не подтверждена.

Для повторной установки используйте скрипты и инструкции README. После обновления файлов уже подключённый агент переключается через меню панели чата `⋯ → Reload Agent`, когда текущая работа закончена. Установка не зависит от временных каталогов исходников и сборки.
